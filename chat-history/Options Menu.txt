● The plan is posted on issue #13
  (https://github.com/Lucas-Light/Pokedex/issues/13#issuecomment-6696546929). No
  code has been changed. The comment also shows how each acceptance criterion
  gets met.

  Approach

  One OptionsSheet, built with React Native's Modal, serves all three grids. The
  homepage and Favorites screens each keep the opened Pokémon in state and
  render the sheet next to their grid, and ⋮ passes { id, name } up. That keeps
  the sheet open when a card disappears or Favorites switches to "No favorites".

  - Closing: a full-screen overlay Pressable handles taps outside, and
    onRequestClose handles Android back. The sheet is a sibling of the overlay,
    so a tap on it outside a row does nothing.
  - Favorite row: it reuses useFavorite unchanged, which already covers saving,
    the disabled state and the failure alert. No data layer changes are needed.
  - Share: Share.share({ message }) with the link inside message, and the result
    is ignored so cancelling does nothing. If it fails, the "Could not share
    Pokémon" alert appears.
  - Keyboard: no new code, because keyboardShouldPersistTaps="never" already
    handles it.

  Your decision

  Sheet animation: the spec rules out custom animation but doesn't say which
  built-in Modal animation to use. I recommend none, the default, which adds
  nothing beyond the spec. With slide, the grey overlay moves up along with the
  sheet, and fade is the softer alternative. Changing it later is a one-prop
  edit.

  - UI:

      FavoritesGrid, Icon, both tab screens
    - Theme: colors.ts, spacing.ts

  - Logic:

  How the code works

  - One sheet per screen: the homepage and Favorites each remember which
    Pokémon's menu is open, in one piece of state. Tapping ⋮ passes { id, name }
    up through the list to the screen. The sheet sits at screen level so it
    survives when a card disappears.
  - The animation: one number, progress, runs from 0 to 1 over 250 ms. The
    overlay uses it directly as opacity, and the sheet turns it into a distance,
    so they always move together. useNativeDriver runs it on the UI thread,
    which keeps it smooth.
  - Closing: every close goes through close(), which runs the number back to 0
    and only then removes the sheet. Without that wait it would vanish
    instantly. isClosing blocks extra taps during that time.
  - The Android buttons fix: a Modal is a separate window. The padding was being
    measured for the main app window, so a SafeAreaProvider inside the Modal
    now measures the sheet's own window.
  - The favorite row: it reuses useFavorite, the same hook as the Detail heart,
    so both read the same SQLite data and always agree. The row waits for the
    data to reload, so it never shows a save that failed.
  - Share: formatShareMessage is a pure function, which makes it easy to unit
    test. The link goes inside the message because React Native's separate url
    field appears to be iOS-only.
