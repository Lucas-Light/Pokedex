  Approach

    next URL is used as the next page, so next: null ends paging without a

    native build and the app must run in Expo Go.

  Decisions for you

     fixed: search stays reachable, and the spinner, error and empty states get
     a clear area below them.
  2. Does Cabinet Grotesk's licence allow bundling? I couldn't confirm this
     because Fontshare's pages didn't return the licence text, so please check
     it there. If it's allowed, I'd bundle only the 800 weight file; if not, the
     spec needs another font.

     Expo Go, so icons look the same on both platforms and the Pokéball is easy
     to draw. The installed expo-symbols needs no new package, but its icons
     differ between iOS and Android.
  4. Which tab icons? The spec doesn't say and I couldn't open the Figma file.
     Unless you tell me otherwise, I'll use a Pokéball for Pokémons and a heart
     for Favorites; exported SVGs would be even better.
  5. Can I add a test runner? The spec asks for unit tests but none is
     installed. I recommend jest-expo and jest, testing only src/lib.

  How the code works

  The route of the data. fetchPokemonPage gets one page from the API.
  usePokemonList wraps that in TanStack Query and turns the pages into one flat
  list of { id, name }. PokemonGrid shows that list, and PokemonCard draws one
  Pokémon. Each layer only knows the one below it, which is what "UI, data and
  logic not mixed" means here.

  Paging. useInfiniteQuery stores pages in a list. After each page,
  getNextPageParam says what comes next, and we simply return the API's own next
  URL. When next is null we return undefined, which tells TanStack there are no
  more pages. This is why we don't need to know the total of 1351, and why the
  jump from ID 1025 to 10001 causes no problems.

  Why the ID comes from the URL. The list position isn't the ID: entry 1026 has
  ID 10001. So getIdFromUrl reads the number at the end of the URL, and the
  image, badge and Detail link all use that real ID.

  The guard in loadNextPage. FlatList can fire onEndReached many times. Only
  fetching when there is a next page, nothing is loading and the last attempt
  didn't fail prevents double requests, and it stops a failed page from retrying
  itself while you scroll.

  The order of the states. PokemonGrid checks them top to bottom: loading, then
  no data (error), then an empty list, then the grid. A later-page failure keeps
  the old data, so it never reaches the error screen and shows in the footer
  instead. The footer checks "fetching" before "error", because the error flag
  stays on during a retry.

  Card size. FlatList with flex: 1 would stretch the single card in the last
  row, because 1351 is odd. So the width is calculated: screen width minus the
  margins and gap, divided by two. The image area is square, so its height
  equals that width, and the name row adds 48. At a width of 390 that gives the
  Figma size of 163×211.

  Fonts and the splash screen. Fonts must be ready before text is drawn, so the
  root layout keeps the splash screen up and renders nothing until useFonts
  reports they loaded or failed. They load at runtime because the config plugin
  needs a native build, and Expo Go doesn't allow that.

  Icons. expo-image draws the SVG files directly, and tintColor recolours them.
  That's how one Pokeball.svg can be white in the active pill, dark when
  inactive, and muted as the placeholder.
