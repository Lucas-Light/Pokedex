  What the API returns

  - Endpoint: PokeAPI has no compare endpoint, so Compare needs one GET
    /pokemon/{id} per Pokémon. That matches product.md. Reusing the ['pokemon',
    'detail', id] query key means a Pokémon that's already loaded needs no new
    request.
  - Stats: stats[] had 6 entries in the same order (HP, Attack, Defense, Special
    Attack, Special Defense, Speed) in all three Pokémon I checked: Charizard,
    pikachu-phd and koraidon-limited-build. Charizard's are 78, 84, 78, 109, 85
    and 100.
  - Stat total: the API doesn't return one, so we'd calculate it
    (Charizard: 534).
  - Other fields: types, height, weight, base_experience and abilities are also
    available, and the About tab already has formatting for them.
  - Gaps in the data:
    - base_experience can be null (clefable-mega).
    - abilities can be empty (zygarde-mega).
    - Weight can be 0 (eternatus-eternamax).
    - Some forms have no HOME image (10083, 10264), but they do have stats, and
      the Pokéball placeholder already covers the image.
  - Pokémon count: the list has 1351 entries, including alternate forms, so the
    picker needs a way to search. The existing search can already do that.
  - Type matchups: /type/{name} has damage_relations, so "fire beats grass" is
    possible. It would be a new endpoint that product.md doesn't list for
    Compare.

  What this affects in the existing specs

  - The app has two tabs, and the Tab Bar in Figma shows only those two. Compare
    is self-designed, so it has no Figma frame.
  - options menu.md lists Compare in the ⋮ menu as out of scope, so adding it
    there means changing that spec.

    the second.
  - c. Both: the row fills slot 1 and takes you to the tab.

  want it smaller, go with a, which leaves the options menu spec unchanged.

  2. How many Pokémon, and how do you pick them?

  Approach

  The two slots hold only Pokémon IDs, in a React context above the navigators,
  so the ⋮ sheet, the Compare tab and the picker can all share them without a
  new package. Each slot loads its Pokémon through the existing
  usePokemonDetail, so it uses the same cache and can retry on its own. All the
  decisions go in src/lib/compare.ts as pure, unit-tested functions. The picker
  is a new stack screen at compare/pick, built from the homepage's search bar,
  grid and search results.

  Two choices for you

  1. What shows below the slots when one slot has failed and the other is empty?
  The spec contradicts itself here: one line says the "Pick two" text shows,
  another says no text shows. Loading has the same gap, because a stats spinner
  is pointless when the other slot is empty.

  I recommend checking in this order, and I'd add it to the spec:
  1. If any slot failed, nothing shows.
  2. If any slot is empty, "Pick two Pokémon to compare" shows.
  3. If any slot is loading, one spinner shows.
  4. Otherwise, the stats card shows.

  2. Should the picker reuse the homepage list or get its own? I recommend
  reusing it through optional props, so paging, search and the keyboard rules
  stay in one place. This touches more files than the spec's Code layout lists,
  and the plan marks those.

  How the code works, in plain language

  - The slots: useCompare.tsx is a shared box holding two numbers, or null for
    empty. It sits above all the screens in _layout.tsx, so the ⋮ menu, tab and
    picker all see the same box. It lives only in memory, which is why a restart
    clears it.
  - The rules: compare.ts has no React in it, only plain functions: numbers go
    in, an answer comes out. That makes it easy to test. For example, addToSlots
    decides where a Pokémon goes, and getHigherSide decides which side turns
    green.
  - Loading the data: useComparePokemon uses the same cache key as Detail, so a
    Pokémon you've already opened appears instantly. enabled: id !== null stops
    an empty slot from making a request.
  - What shows below the slots: each slot gets one status: empty, loading,
    failed or loaded. getCompareArea looks at both and picks one answer, in the
    order you approved.
  - The picker: it's the homepage's grid and search with two small differences.
    With no onOptions there's no ⋮, and with onPick a tap fills the slot instead
    of opening Detail. excludePokemon removes the Pokémon in the other slot
    before the list renders, which is how a Pokémon can't be compared with
    itself.
  - ✕ and Retry: they sit next to the slot's button, not inside it, because iOS
    screen readers can't reach a button inside a button.
