  Evolution takes three requests in a row: /pokemon/{id}, then the species, then
  evolution_chain.url. The chain is a nested tree of evolves_to, and each node
  gives a species name and URL. The ID comes from that URL, and every species ID
  has a matching Pokémon ID.

● The plan is posted on issue #5
  (https://github.com/Lucas-Light/Pokedex/issues/5#issuecomment-6690023936), and
  no code has been changed. Here's a shortened version; the full files list and
  the acceptance criteria table with what to test on the phone are in the
  comment.

  Approach

  - Screen: the route stays thin and renders one PokemonDetail component with
    key={id}, so a new Pokémon always starts on About at the top. The native
    header is replaced by our own pinned bar above a ScrollView.
  - Back: evolution cards use router.replace, so there's only ever one detail
    page on the stack. The back button, Android back and iOS swipe then all
    return to whatever opened Detail, including Favorites later, with no special
    cases.
  - Data: usePokemonDetail fetches the Pokémon, and useEvolutionChain does the
    species and chain requests in one query. The Evolution tab only mounts when
    opened, and staleTime: Infinity stops it reloading when you switch back.
  - Pinned name: it's driven by the scroll offset compared to the big name's
    measured position, with no Reanimated.
  - Image overlap: a background band sits behind the top 150 of the image, so
    the edge moves down when a long name wraps.
  - Dashed line: it's built from small Views, because React Native's dashed
    borders aren't reliable on a single side.

  Files

  - UI:
    - New: PokemonDetail, DetailBar, DetailHeader, DetailTabs, AboutTab,
      StatsTab, EvolutionTab, EvolutionCard and PokemonImage.
    - Changed: pokemon/[id].tsx, _layout.tsx, PokemonCard (no visual change) and

     useEvolutionChain.ts:12 (src/hooks/useEvolutionChain.ts#L12) fixes it.

  How the code works

  - The route: [id].tsx (src/app/pokemon/%5Bid%5D.tsx) reads the ID from the URL
    and passes it on. key={id} tells React to treat each Pokémon as a brand-new
    component, so it always starts on About at the top.
  - Why back always works: a stack is like a pile of screens. The list is at the
    bottom and Detail sits on top. Tapping an evolution card uses replace,
    which swaps the top screen instead of adding another, so back always lands
    on whatever opened Detail.
  - Three layers:
    - src/api fetches raw JSON.
    - src/lib turns it into display-ready values, such as 69 into 6.9 kg. These
      are plain functions, so they can be tested without a phone.
    - src/hooks connects them with TanStack Query, which handles caching,
      loading and errors. The select option runs the conversion, so components
      only get finished data.
  - Loading and error: isPending means there's no data yet and a request is
    running, so the spinner shows. If it's not pending and there's still no
    data, the request failed, so the error shows. Retry goes back to pending,
    which brings the spinner back.
  - Evolution chain: the API returns a tree, where each Pokémon holds a list of
    its evolutions. flattenEvolutionChain calls itself on each branch to turn
    the tree into one flat list. The chain needs two requests, because the
    Pokémon points to its species and the species points to the chain.
  - Lazy loading: EvolutionTab only exists while its tab is open, and that's
    when its query starts. So the chain isn't fetched until someone opens the
    tab, without any extra code.
  - Pinned name: the header measures where the big name ends, and the scroll
    handler compares the scroll position to that number. It stores a simple
    true/false, so the page only re-renders when the answer changes, not on
    every scroll event.
  - Image overlap: the page is white, and a blue band sits behind the top 150 of
    the 200-high image. The bottom 50 of the image therefore sits on white, and
    the edge moves down with a wrapped name.
